# Spike: Tornado Nova pool on the original Circom 0.5 toolchain

Option A of [docs/shielded-pool.md](../../docs/shielded-pool.md). Testnet-only, single-party trusted setup, not audited.

Nova source: `tornadocash/tornado-nova` @ `f9264eeffe48bf5e04e19d8086ee6ec58cdf0d9e` (ISC per package.json).

## What's here

| Path | What |
| --- | --- |
| `circuits/` | Nova's `transaction.circom`, `merkleProof.circom`, `keypair.circom` byte-identical; `transaction2/16.circom` with tree height 5 → 23 (Nova's own `circuit_prod` does the same) |
| `contracts/src/ShieldedPool.sol` | Stripped `TornadoPool` in Solidity 0.8: tree, nullifiers, `transact(Proof, ExtData)`, extDataHash binding, `publicAmount = extAmount - fee`, relayer fee in token, deposit cap (constructor). Plain ERC-20 `transferFrom` deposits |
| `contracts/src/MerkleTreeWithHistory.sol` | Nova's, ported to 0.8, initializer moved into the constructor |
| `contracts/src/Verifier2.sol`, `Verifier16.sol` | Generated by `scripts/setup.js` from this spike's keys |
| `contracts/src/MockAUSD.sol` | 6-decimal ERC-20 |
| `contracts/test/ShieldedPool.t.sol` | Proof-free forge tests (cap, unknown root, extData binding, publicAmount math) |
| `src/nova.js` | Nova's `utils/keypair/utxo/prover/index.js` in one file on ethers v5 (no hardhat) |
| `scripts/setup.js` | Powers of tau + Groth16 setup through the snarkjs JS API |
| `scripts/e2e.js` | Full scenario on a fresh anvil |

Removed from Nova: OmniBridge/ERC-677 (`onTokenBridged`, `onTransact`), L1 unwrapper, `isL1Withdrawal`/`l1Fee` (also gone from `ExtData` and its hash), CrossChainGuard/proxy/initializer, multisig/`rescueTokens`/`configureLimits`, `register()`/`Account`, `lastBalance`.
`ExtData = (address recipient, int256 extAmount, address relayer, uint256 fee, bytes encryptedOutput1, bytes encryptedOutput2)`.

## Reproduce

Node 22, Foundry 1.7.1 at `~/.foundry/bin`, Git Bash on Windows. Run everything from this folder.

```bash
git clone https://github.com/tornadocash/tornado-nova upstream   # reference only, gitignored
git clone --depth 1 https://github.com/foundry-rs/forge-std contracts/lib/forge-std
npm install                       # circom 0.5.45 + Tornado's circomlib/snarkjs forks (~2 min)
mkdir -p build && npm run circuits   # ~7 s + ~44 s
npm run setup                     # local ptau 2^17 + groth16 keys + Verifier*.sol (~25 min, see below)
npm run contracts                 # forge build + forge test (6 proof-free tests)
npm run e2e                       # spawns anvil on :8547, runs the scenario (~25 s)
```

## Toolchain that worked

| Piece | Version |
| --- | --- |
| circom | 0.5.45 (npm, JS compiler; runs unchanged on Node 22) |
| circomlib | tornadocash fork `d20d53411d1bef61f38c99a8b36d5d0cc4836aa1` (v0.4.1) |
| snarkjs | tornadocash fork `f37f146948f3b28086493e71512006b030588fc2` (v0.4.5) |
| ffjavascript | 0.2.38 top level (snarkjs pulls 0.2.36) |
| fixed-merkle-tree / eth-sig-util / ethers | 0.5.1 / 3.0.1 / 5.7.2 |
| solc / forge / anvil | 0.8.28 / 1.7.1 / 1.7.1 |

What broke and the workaround:
- **snarkjs 0.4.5 CLI fails on Windows**: it resolves its own `package.json` from `new URL(...).pathname`, giving `C:\C:\...\package.json` (ENOENT). Every snarkjs step is called through the JS API in `scripts/setup.js` instead. Would work as-is on Linux/macOS.
- `require.resolve('snarkjs/templates/...')` is blocked by the package `exports` map; the template is read by path.
- The verifier template is `pragma ^0.7.0`; `setup.js` rewrites it to `^0.8.0` and renames `Pairing` → `Pairing2`/`Pairing16` so both verifiers compile in one Foundry project. No other change; it compiles unmodified under 0.8.28.
- Circuits needed **no** changes for the old toolchain (only the tree height constant).
- `fixed-merkle-tree@0.5.1` drags in an even older circomlib (0.0.20) and snarkjs (0.1.20) fork; harmless.

Monad estimate = anvil gas + precompile delta only. Groth16 verify = n ecMul + n ecAdd + one 4-pair ecPairing (n = public inputs).
Ethereum: ecMul 6,000, ecAdd 150, pairing 45,000 + 34,000·4 = 181,000. Monad: ecMul 30,000, pairing 225,000 + 170,000·4 = 905,000, ecAdd assumed 5× = 750 (rounding error either way).
Delta: transaction2 (n = 7) +896k; transaction16 (n = 21) +1.24M. Other Monad repricings (cold storage) not modelled; Monad also bills the gas *limit*, so set limits tight.

Where the ~950k goes on Ethereum pricing: verification ~240k; the Merkle insert is 23 external Poseidon calls (~19k each, ~450k); the rest is nullifier/root/leaf storage, events with two ~120-byte ciphertexts, and token transfers. A lower tree height or a cheaper on-chain Poseidon is the obvious gas lever outside the verifier.

## End-to-end scenario (`npm run e2e`, all assertions pass)

1. Stealth EOA S1 deposits 10 AUSD into a note for Bob; S2 deposits 15. Bob finds both by trial-decrypting `NewCommitment` logs.
2. Bob merges 10 + 15 → 25 (transaction2, relayer submits, fee 0).
3. Bob sends 20 to Alice (built from Alice's public `Keypair.address()` only), 5 change.
4. Alice withdraws **12 gross**: 11.9 AUSD to a fresh EOA, 0.1 AUSD fee to the relayer, which submits the tx; Alice keeps 8. The fresh EOA has 0 native balance before and after. (`extAmount = -11.9`, `fee = 0.1`, `publicAmount = -12`. The brief's "12 + 0.1 fee + 8 change" doesn't sum to 20; this reading keeps 8 change.)
5. S3 and S4 deposit 1 and 2 for Bob; Bob merges 5 + 1 + 2 → 8 with **transaction16** (13 zero-padding inputs).
6. Negative checks:
   - Deposit above the 1,000 AUSD cap reverts.
   - Replaying the merge (same proof and extData) reverts with `Input is already spent`; a *new* proof spending the already-spent 10 note also reverts.
   - Changing `recipient` or `fee` in extData after proving reverts with `Incorrect external data hash`.
   - Overdraw (claim 30 out of a 20 note) fails witness generation (`Constraint doesn't match`, the amount invariant).
   - A fake 100 note proved against a locally forged tree produces a valid proof, but the pool reverts with `Invalid merkle root`.
7. Final token balances: pool 16, fresh EOA 11.9, relayer 0.1 (= 10 + 15 + 1 + 2 − 12); Bob 8 and Alice 8 shielded.

## Blockers / caveats

- None blocking. The old toolchain installs and runs on Node 22 / Windows with the CLI workaround above.
- The toolchain is unmaintained (circom 0.5 and the snarkjs fork are deprecated on npm) and pulls ~730 packages with many deprecated transitive deps. Fine for a spike, but don't build production on it.
- `preparePhase2` in snarkjs 0.4.5 is slow (23 min at 2^17 under load). A downloaded Hermez/PPoT ptau would skip it and also be the right input for a real ceremony.
- Single contributor, random entropy, no beacon: **testnet only**.
