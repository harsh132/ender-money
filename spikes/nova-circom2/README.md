# Spike: Tornado Nova ported to Circom 2

This spike covers Option A in [docs/shielded-pool.md](../../docs/shielded-pool.md). It takes
[tornado-nova](https://github.com/tornadocash/tornado-nova) (commit `f9264ee`, ISC), strips it down to a minimal
ERC-20 shielded pool, ports the circuits to current Circom 2, circomlib and snarkjs, and runs it end to end on a
local anvil chain. **Testnet only:** the trusted setup is single-party and nothing here is audited.

**Status:** everything works. The ported circuits compile, the keys are generated locally, the Foundry tests
pass, and the full end-to-end scenario passes on anvil, including every negative check.

## Layout

| `contracts/MockAUSD.sol` | ERC-20 with 6 decimals and an open `mint` |
| `contracts/generated/Verifier{2,16}.sol` | Generated by snarkjs from our keys (gitignored) |
| `src/` | Nova's client (`utils`, `keypair`, `utxo`, `index` + `prover`) ported to ESM, BigInt, viem and snarkjs 0.7 |
| `scripts/ptau.sh` | Local powers of tau (power 17) |
| `scripts/setup.sh` | Compile, Groth16 setup, one contribution and verifier export for each circuit |
| `scripts/circuit-test.mjs` | Witness-level checks: valid cases pass and every constraint family rejects a bad witness |
| `scripts/e2e.mjs` | Full scenario on anvil (starts its own anvil on port 18547) |
| `test/*.t.sol` | Forge tests: zeros/hasher consistency, publicAmount, deposit cap, unknown root, hasher gas |

## Reproduce

Run these in Git Bash from `spikes/nova-circom2/`. You need Node 22 and Foundry in `~/.foundry/bin`.

```bash
# toolchain (local to this folder)
mkdir -p bin && curl -L -o bin/circom.exe https://github.com/iden3/circom/releases/download/v2.2.3/circom-windows-amd64.exe
#   sha256 e43f132ee6f0aa79b705beceb59c2a7e6a54d7bdeab917ca34e9fc1951d185e1, `bin/circom.exe --version` -> 2.2.3
npm ci
git clone --depth 1 https://github.com/foundry-rs/forge-std lib/forge-std   # NOT `forge install` (see Problems)
export PATH=$PATH:~/.foundry/bin

npm run ptau            # ~25 min, writes build/pot17_final.ptau
npm run setup           # ~6 min: circuits, zkeys, contracts/generated/Verifier{2,16}.sol, build/Hasher.json
npm run test:circuits   # witness-level constraint checks
forge test              # proof-free contract tests
npm run e2e             # anvil end to end; results go to build/e2e-results.json and stdout
```

The forge hasher-gas test also measures Nova's fork hasher if `build/HasherFork.json` exists. To create it, in a temp dir run
`npm i circom@0.5.46 web3-utils@1 "circomlib@git+https://github.com/tornadocash/circomlib.git#d20d53411d1bef61f38c99a8b36d5d0cc4836aa1"`, then
`node -e "require('fs').writeFileSync('<spike>/build/HasherFork.json', JSON.stringify({bytecode: require('circomlib/src/poseidon_gencontract.js').createCode(2)}))"`.
The same temp install gives the original constraint counts: `npx circom -r t2.r1cs <nova>/circuits/transaction2.circom` with the height set to 23.

`setup.sh` appends each step's duration to `build/timings.log`.

The verification-only figures come from calling each verifier in its own transaction with an explicit gas limit,
then subtracting 21,000 and the calldata cost.

**Why transact costs about 200k more than the Circom 0.5 spike (about 1.0M).** Each insert does 23 on-chain
Poseidon(2) calls. The standard Poseidon costs 29.6k per call against 19.7k for Nova's fork, which comes to about
228k per transact. Swapping in a cheaper standard-Poseidon contract (for example the `poseidon-solidity` PoseidonT3
library) would win most of that back without changing hash outputs. Not done here.

### Monad verification estimate

Monad prices the BN254 precompiles higher: ecAdd 300 (Ethereum 150), ecMul 30,000 (6,000), and ecPairing
225,000 + 170,000 per pair (45,000 + 34,000 per pair). Groth16 verification runs one ecMul and one ecAdd per public
input and one 4-pair pairing. So:

| | Ethereum (measured) | Precompile delta | Monad estimate |
| --- | --- | --- | --- |
| tx2 verify (7 public inputs) | 228,804 | +893,050 | **~1.12M** |
| tx16 verify (21 public inputs) | 321,862 | +1,231,150 | **~1.55M** |
| Full tx2 transact | ~1.18M | +893k | ~2.07M |
| Full tx16 transact | 1.62M | +1.23M | ~2.85M |

The full-transact estimates leave out Monad's other repricings (cold SLOAD and account access). Monad also charges
the gas *limit*, not the gas used, so limits need to be tight.

### End-to-end scenario (`scripts/e2e.mjs`, all pass)

Accounts: anvil dev accounts S1–S5 stand in for Bob's stealth addresses, plus a relayer EOA. The fresh EOA is a
freshly generated key that never sends a transaction or holds native gas. Bob and Alice are shielded keypairs. Each
wallet finds its notes by trial-decrypting the `NewCommitment` logs (Nova's x25519-xsalsa20-poly1305 encryption).

1. S1 deposits 10 AUSD to a note for Bob, and S2 deposits 15.
2. Bob merges the 10 and 15 notes into one 25 note (tx2).
3. Bob pays Alice 20 privately and keeps a 5 change note. Bob only sees Alice's 64-byte shielded address.
4. Alice withdraws 12 from her shielded balance: `extAmount = -11.9`, `fee = 0.1`, giving 11.9 to the fresh EOA and
   0.1 to the relayer, with an 8 change note. The relayer submits the transaction. The fresh EOA's native balance
   stays 0 before and after.
5. S3, S4 and S5 deposit 1, 2 and 3 for Bob. Bob merges his 4 notes (5+1+2+3) into one 11 note with transaction16.
6. Negative checks:
   - Tampered recipient reverts with `Incorrect external data hash`.
   - Tampered fee with a recomputed extDataHash and publicAmount reverts with `Invalid transaction proof`.
   - Withdrawing 30 from a 20 note fails to prove (sum constraint).
   - Claiming the 20 note holds 30 fails to prove (commitment not in the tree).
   - Replaying the merge transaction reverts with `Input is already spent`.
   - A fresh proof re-spending Bob's already-spent 10 note reverts with `Input is already spent`.
   - Depositing 1,001 against a 1,000 cap reverts with `amount is larger than maximumDepositAmount`.
7. Final balances: pool **19** (Alice 8 + Bob 11), fresh EOA **11.9**, relayer **0.1**. The local tree root equals
   the on-chain `getLastRoot()`.

## Port changes

### Circuits (logic unchanged)

1. `pragma circom 2.2.0;` was added, includes now end with `;`, and circomlib is resolved through `-l node_modules`.
   `comparators.circom` is included explicitly; Nova got it transitively.
2. `signal private input x` became `signal input x`. In Circom 2, inputs are private unless the main component
   lists them as public.
3. `component main {public [root, publicAmount, extDataHash, inputNullifier, outputCommitment]}`. Circom orders
   public signals by declaration, which matches Nova's verifier input order and the contract's.
4. In `MerkleProof`, the signal ternary `switcher[i].L <== i == 0 ? leaf : hasher[i-1].out` became an `if/else`
   on the compile-time `i`. The wiring is the same.
5. **Poseidon.** Nova used Tornado's circomlib fork (`d20d534`, v0.4.1). Its Poseidon uses 35 partial rounds for
   every width and different round constants. Current circomlib uses the standard parameters (8 full rounds;
   56/57/56 partial rounds for t = 2/3/4), which are also the paper's recommended values. So hashes differ (for
   example, `Poseidon(1,2)` is `7995…6345` in the fork and `7853…3530` in the standard version). As a result,
   commitments, nullifiers and tree zeros are **not bit-compatible with Nova's deployment**, the
   `MerkleTreeWithHistory.zeros()` table was regenerated, and the EVM hasher comes from circomlibjs. The semantics
   are unchanged. This change accounts for the higher constraint counts and the higher hasher gas.
6. Circuits are compiled with `--O2`. circom 2.2.3 defaults to `--O1`, which keeps linear constraints; circom 0.5
   simplified fully by default, so `--O2` is the like-for-like setting. Every template, signal and constraint is
   otherwise as in Nova, and the unused `zeroLeaf` template parameter is kept.

### How equivalence was checked

- **Same signals.** Compiled with Nova's fork Poseidon swapped in, the port has exactly the same number of
  labelled signals as the circom 0.5 build of the original: 43,315 for tx2 and 330,567 for tx16.
- **Same constraints, apart from two explained differences.** With the fork Poseidon, the port has 10,130 / 75,027
  constraints against Nova's 10,132 / 75,148. The difference is exactly 1 + (number of nullifier pairs), i.e. 1 + 1
  for tx2 and 1 + 120 for tx16. I confirmed both causes on a probe circuit with each compiler (`snarkjs r1cs print`):
  - circom 0.5 keeps the trivially true row `(b - a) * 0 = 0` that `IsEqual().out === 0` leaves behind.
    circom 2 drops it; the row `(b - a) * inv = 1` that actually enforces `a ≠ b` is kept in both.
  - circom 0.5 keeps the linear sum row `sumIns + publicAmount = sumOuts`. circom 2 `--O2` eliminates it by
    substitution (one wire fewer). That preserves the solution set.
- **No unsafe assignments.** `--inspect` reports nothing beyond CA02 warnings for unused `Num2Bits` output bits.
  Those bits are constrained inside `Num2Bits`; they are range checks. The only `<--` assignments are circomlib's
  `IsZero` (inverse) and `Num2Bits` (bits), each followed by its constraining equations. The port adds none.
- **Witness tests** (`scripts/circuit-test.mjs`). Deposits, merges, withdrawals and a 16-input merge pass, and a
  merge witness satisfies the R1CS (`wtns check`). Each of these fails:
  - sum inflation,
  - duplicate input or nullifier,
  - output ≥ 2^248 (field wraparound),
  - wrong owner key,
  - wrong nullifier,
  - wrong root with a non-zero input,
  - wrong path index,
  - output commitment mismatch,
  - inflated input amount.
- **On chain.** The end-to-end proofs verify against the generated verifiers, and the tampering and replay cases revert.

### Contracts (`TornadoPool` → `ShieldedPool`, Solidity 0.7 → ^0.8.24)

**Kept:**
- `MerkleTreeWithHistory`: height 23, 100-root history, pairwise insert
- the nullifier set
- `transact(Proof, ExtData)`
- `extDataHash = keccak256(abi.encode(extData)) % p`
- `publicAmount = extAmount - fee`, with the same `MAX_EXT_AMOUNT` / `MAX_FEE` bounds
- relayer fee paid in the token
- Verifier2 and Verifier16
- the `NewCommitment` and `NewNullifier` events
- `nonReentrant`

**Removed:**
- OmniBridge, ERC-677, `onTokenBridged` and `onTransact`
- `L1Unwrapper`, `isL1Withdrawal` and `l1Fee` (these also leave the `ExtData` struct and therefore the hash encoding)
- `CrossChainGuard`, the upgradeable proxy and `initialize`
- the multisig, `configureLimits` and `rescueTokens`
- `register`, `registerAndTransact`, `Account` and the `PublicKey` event
- `lastBalance`, `MIN_EXT_AMOUNT_LIMIT` and the storage gap

**Changed:**
- Deposits are a plain `safeTransferFrom(msg.sender, pool, extAmount)` (OpenZeppelin SafeERC20), and the cap is
  checked before pulling funds.
- `maximumDepositAmount` is an immutable constructor parameter.
- The snarkjs 0.7 verifier takes `(a, b, c, pub)`. The pool keeps Nova's 256-byte `proof` and `abi.decode`s it,
  and the client keeps Nova's limb packing.

## Problems and notes

- **snarkjs verifiers return `false` instead of reverting when their precompile calls run out of gas.**
  `eth_estimateGas` on a bare `verifyProof` transaction therefore finds a limit (here the EIP-7623 calldata floor)
  where the call "succeeds" with `false`. My first verify-gas measurement read 11.6k because of this. The pool is
  safe because it `require`s the result, but never budget a verifier call from `estimateGas`.
- **`forge install` writes to the git root.** Run in this subfolder of the ender-money repo, it created
  `ender-money/lib/forge-std`. I moved that into `spikes/nova-circom2/lib/` (the repo root is clean again). Use the
  `git clone` line above instead.
- Local ptau generation is practical but slow: the phase-2 preparation takes about 24 minutes at power 17.
  Everything else in setup takes about 6 minutes.
- No circomspect or Picus run: both need Rust, which isn't installed. They are worth running before an audit.
- Cross-check against `minimal-shielded-pool` (Circom 2): it also uses the standard circomlib Poseidon. Unlike
  Nova, it range-checks *input* values and domain-separates nullifiers by chain and pool. Nova's design omits both
  (inputs were range-checked as outputs, and the root ties a proof to one tree), and I kept Nova's design.
  Worth raising in the audit.
- Nova's dummy (zero-amount) inputs skip the root check by design, which is unchanged here.
